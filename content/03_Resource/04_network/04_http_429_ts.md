# 피크 시간대에만 외부 API 호출이 실패한 이유

<!-- 실제 내용을 채우면서 제목을 사례에 맞게 다듬는다. -->

## 문제 상황

- 외부 OpenAPI를 호출하는 서비스
- 피크 시간대에 요청 실패가 증가
- 공개할 수 없는 식별 정보는 일반화해서 적는다

## 시스템 구성

```text
우리 서비스
→ HTTP Client
→ 외부 OpenAPI
```

## 진단 과정

- HTTP Status 확인 (429 외 다른 오류와 구분)
- 시간대별 요청량과 실패율 비교
- 응답 Header 확인 (`Retry-After`, 잔여 한도 관련 Header)
- 기존 Retry 조건, 간격, 최대 횟수 확인
- 재시도가 요청량에 얼마나 기여했는지 확인

## 당시 몰랐던 개념

- Rate Limit의 적용 단위 (사용자 / API key / IP / 서버 전체)
- `Retry-After`의 형식과 우선순위
- 재시도가 실패 요청 수를 다시 늘린다는 점

## 추가로 공부한 개념

- Retry가 장애를 악화시키는 과정
- Exponential Backoff
- Jitter
- Retry 횟수와 전체 deadline 제한
- 멱등성과 재시도 가능한 요청의 구분

## 지금 다시 대응한다면

```text
HTTP Status
→ 제한 주체와 단위
→ 응답 Header
→ 우리 쪽 요청 패턴
→ Retry 전략
```

순서로 확인하고, 재시도 설정을 손대기 전에 요청량부터 본다.
