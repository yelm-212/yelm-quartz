# Network 종합 트러블슈팅 사례

## 사례 선정 기준

- 하나의 요청이 사용자에게 도달하기까지 여러 계층이 함께 영향을 준 공개 사례를 선택한다.
- 장애를 겪은 조직이 직접 공개한 기술 블로그, 발표 자료, 사후 분석 문서를 우선 사용한다.
- 처음 관찰된 증상과 실제 원인을 구분할 수 있고, 조사 과정이나 근거가 공개된 사례를 선택한다.

## 3. 확인할 로그, 메트릭, 명령어 정의

### DNS

<!-- 조회 결과, 응답 코드, authoritative server, TTL, resolver별 차이를 확인한다. -->

```bash
dig example.com +noall +answer
dig +trace example.com
```

### 연결과 TLS

<!-- 단계별 소요 시간으로 어느 구간에서 지연되는지 좁힌다. 인증서와 ALPN도 함께 확인한다. -->

```bash
# DNS, connection, TLS, TTFB 단계별 소요 시간
curl -sS -o /dev/null -w 'dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer} total=%{time_total}\n' https://example.com

# TLS handshake와 certificate chain
openssl s_client -connect example.com:443 -servername example.com </dev/null
```

### HTTP와 Intermediary

<!-- 상태 코드 분포, 응답 Header, Proxy와 Load Balancer의 access/error log, target health를 확인한다. -->

```bash
ss -s
```
