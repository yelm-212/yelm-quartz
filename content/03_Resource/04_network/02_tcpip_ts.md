# TCP 연결 장애 트러블슈팅 사례

## 사례 선정 기준

- TCP 연결 실패, Connection Storm, Local Port 고갈, TIME_WAIT 증가 중 하나와 관련된 공개 사례를 선택한다.
- 장애를 겪은 조직이 직접 공개한 기술 블로그, 발표 자료, 사후 분석 문서를 우선 사용한다.
- 처음 관찰된 증상과 실제 원인을 구분할 수 있고, 조사 과정이나 근거가 공개된 사례를 선택한다.

## 2. TCP 연결 관점에서 원인 가설 설정

```text
연결 시도
→ 대상 IP와 Port
→ TCP 연결 수립
→ Socket State
→ Local Port 사용량
→ TIME_WAIT
→ Server Accept Queue
```

| 우선순위 | 구간 | 가설 | 가설의 근거 | 예상되는 관찰 결과 |
| -------- | ---- | ---- | ----------- | ------------------ |

| 2        |      |      |             |                    |
| 3        |      |      |             |                    |

## 3. 확인할 로그, 메트릭, 명령어 정의

### 연결 시도와 실패 지점

<!-- timeout, connection refused, connection reset을 구분한다. 각각 어느 구간의 문제를 가리키는지 함께 정리한다. -->

```bash
nc -vz example.com 443
curl -v --connect-timeout 3 https://example.com
```

### Socket State

<!-- 상태별 연결 수 분포와, 어떤 상태가 비정상적으로 많은지 확인한다. -->

```bash
# TCP 소켓 상태 요약
ss -s

# TCP 연결을 상태별로 집계
ss -tan | awk 'NR > 1 { count[$1]++ } END { for (state in count) print state, count[state] }'
```

### Local Port와 TIME_WAIT

<!-- ephemeral port 범위와 사용량, TIME_WAIT 연결 수, 같은 대상으로 향하는 연결이 반복 생성되는지 확인한다. -->

```bash
# ephemeral port 범위 확인
cat /proc/sys/net/ipv4/ip_local_port_range

# 대상별 연결 수 상위 확인
ss -tan | awk 'NR > 1 { print $5 }' | sort | uniq -c | sort -rn | head
```

### Server 측 Queue

<!-- accept queue overflow와 SYN 재전송 여부를 확인한다. -->

```bash
# listen socket의 backlog와 대기 중인 연결 수
ss -ltn

# 연결 관련 커널 통계
netstat -s | grep -i -E 'listen|overflow|retrans'
```
