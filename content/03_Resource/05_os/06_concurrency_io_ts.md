# 동시성과 I/O 트러블슈팅 사례

## 사례 선정 기준

- Blocking I/O로 인한 요청 적체, Thread Pool Exhaustion, Lock 대기 또는 Deadlock, Event Loop에서 Blocking 작업을 실행해 발생한 지연 중 하나와 관련된 공개 사례를 선택한다.
- 장애를 겪은 조직이 직접 공개한 기술 블로그, 발표 자료, 사후 분석 문서를 우선 사용한다.
- 처음 관찰된 증상과 실제 원인을 구분할 수 있고, 조사 과정이나 근거가 공개된 사례를 선택한다.

## 3. 확인할 로그, 메트릭, 명령어 정의

### CPU와 대기

<!-- CPU 사용률, iowait, run queue 길이를 확인해 연산 부하와 대기를 구분한다. -->

```bash
vmstat 1
```

### Thread State

<!-- 실행 중인 Thread 수와 각 Thread가 어디서 대기하는지 확인한다. -->

```bash
ps -eLo pid,tid,stat,wchan:30,comm | head
```

### Lock 대기와 I/O 대기 구분

<!-- Thread State, 대기 지점, CPU 사용률 조합으로 두 상황을 어떻게 구분할지 정리한다. -->

```bash
# process가 대기 중인 system call 확인
strace -f -p <pid> -c
```

<!-- `strace`는 대상 process를 느리게 만들 수 있으므로 운영 환경에서 사용할 조건을 함께 기록한다. -->

### 연결과 Thread Pool

<!-- 열려 있는 socket과 연결 상태, Active Thread 수, Queue 길이, 획득 대기 시간을 확인한다. -->

```bash
ss -tanp
```
